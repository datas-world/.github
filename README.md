# datas-world/.github

Organisation-wide community health defaults for [datas-world](https://github.com/datas-world).

GitHub applies the files in this repository to every repository the organisation
owns — public or private — that does not provide its own file of the same type.
Repository-local files always win.

| File | Applies to |
| --- | --- |
| [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) | Issues, pull requests and discussions |
| [CONTRIBUTING.md](CONTRIBUTING.md) | Repositories open to contributions |
| [SECURITY.md](SECURITY.md) | All repositories |
| [SUPPORT.md](SUPPORT.md) | All repositories |
| [.github/ISSUE_TEMPLATE/](.github/ISSUE_TEMPLATE/) | New-issue forms |
| [.github/PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md) | New pull requests |
| [profile/README.md](profile/README.md) | The organisation profile page |

A default `LICENSE` cannot be supplied this way. Every repository carries its own.

## What is deliberately not here

Reusable workflows, the file-sync configuration, label definitions, workflow and
config stubs, and the AI-agent customisation live in
[datas-world/org-workflows](https://github.com/datas-world/org-workflows), which is
private. Nothing in that repository propagates through the community-health
mechanism, so the two concerns are kept apart: this repository is public-facing
policy, that one is internal automation.

Copilot instructions, `AGENTS.md`, dev containers and workspace settings are
per-repository in GitHub's design and are never inherited from here.
