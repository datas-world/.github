# Support

These are personal and professional projects maintained in spare time. There is no
service-level agreement, no guaranteed response time, and no commitment to fix any
particular problem.

## Where to ask

- **A bug, or something that does not work as documented** — open an issue in the
  repository concerned, using the Bug Report form.
- **A missing capability** — open an issue using the Feature Request form.
- **A security vulnerability** — do not open an issue. Follow
  [SECURITY.md](SECURITY.md).
- **A question about how to use something** — open an issue; if the repository has
  Discussions enabled, prefer that.

## Before opening an issue

Read the repository's own `README.md` first. Many repositories document known
limitations, unsupported configurations, or an explicit "not maintained" status,
and several are published as reference artefacts rather than as software intended
for production use.

Search existing open and closed issues. Duplicates are closed without discussion.

## What helps

State what you did, what you expected, and what happened instead, with enough
detail that someone else can reproduce it. Include versions and the platform.
Reports that cannot be reproduced are closed.
